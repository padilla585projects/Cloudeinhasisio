v3.10.2 (2026-05-10) — AUTOREPARACIÓN: Jarvis detecta sus errores y se repara solo
────────────────────────────────────────────────────────────────────────────────

NUEVO — bootSelfCheck() + autoRepair():
- Al arrancar, Jarvis lee sus propios logs via /addons/jarvis_ai_agent/logs
- Si detecta SyntaxError, TypeError, reinicios en bucle u otros errores:
  1. Espera 30s para que el sistema se estabilice
  2. Llama a Claude (Haiku) con el log + su propio código fuente
  3. Claude analiza el error y devuelve un patch mínimo (errorLine → fixedLine)
  4. Si confianza es high/medium y el fragmento existe en el código: aplica el fix
  5. Escribe el server.js corregido y se reinicia solo con la API del supervisor
  6. Si la confianza es baja: crea un pensamiento crítico para que el usuario lo revise
- Aprende de cada reparación: registra causa + solución en learnings.json

NUEVO — Sección AUTOREPARACIÓN en el system prompt:
- Jarvis sabe explícitamente cómo repararse: get_system_logs → read_file →
  localizar error → write_file con fix → ha_supervisor restart_addon → verificar
- No pide permiso. En una emergencia de boot, actúa y luego informa.
- Conoce los errores de sintaxis más comunes en Node.js

v3.10.0 (2026-05-10) — RED LOCAL + ARCHIVOS DEL PC + AGENTES IA EN LA RED
────────────────────────────────────────────────────────────────────────────────

NUEVO — Tool `network` (acceso completo a la red de casa):
- arp_table: lista todos los dispositivos vistos recientemente en la red (tabla ARP)
- scan_subnet: ping sweep de toda la subred para descubrir hosts activos
- ping: comprobar si un dispositivo responde y medir latencia
- port_scan: detectar qué puertos tiene abiertos un host (TCP)
- http_request: llamar a la API REST de cualquier dispositivo de la red local
- discover_agents: detectar automáticamente agentes IA en la red (Ollama, LM Studio,
  LocalAI, Open WebUI, otro Jarvis, Text Gen WebUI, AnythingLLM)
- wol: Wake-on-LAN — enviar magic packet para encender un PC remotamente
- config.yaml: host_network=true para que el container tenga acceso real a la LAN
- Dockerfile: añadidos iproute2 e iputils para comandos ip/ping en Alpine

NUEVO — Tool `local_file` (archivos del ordenador del usuario):
- Lee y navega archivos del PC desde el que el usuario habla con Jarvis
- Botón "📁 PC" en el header — el usuario selecciona una carpeta con el diálogo del OS
- Usa File System Access API del navegador (Chrome/Edge) — sin instalar nada
- Cuando Jarvis llama a local_file, el servidor envía un SSE al browser, el browser
  lee el archivo con permisos del usuario y devuelve el contenido vía /api/local_response
- Soporta: read (leer archivo), list (explorar directorio), search (buscar por nombre)
- El botón cambia a verde y muestra el nombre de la carpeta conectada
- Archivos binarios (imágenes/PDFs): redirige al botón 📎

NUEVO — Tool `agent_chat` (hablar con otros agentes IA):
- Envía mensajes a agentes IA descubiertos en la red y recibe su respuesta
- Protocolos soportados: Ollama, OpenAI-compatible (LM Studio, LocalAI), Jarvis, custom
- Flujo típico: discover_agents → elegir agente → agent_chat
