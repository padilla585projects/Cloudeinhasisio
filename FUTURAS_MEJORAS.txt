SPRINT POOL — OPTIMIZAR EL PAYLOAD HACIA EL POOL LOCAL                  ALTA
================================================================================
Acordado con el equipo del pool el 04-10-2026. Cada vuelta del bucle agentico
anade 2.000-2.900 tokens NUEVOS al prompt (el contexto crecio 5k -> 14k en 5
vueltas). Las 96 tools se reutilizan de cache; lo nuevo hay que leerlo:
25-30 s/vuelta incluso con la GPU libre (~90 tok/s). Mi timeout es 45 s.
Orden de ataque (toca el bucle agentico: hacerlo con calma y probando):
[v] 1. Truncar resultados de tools (HECHO v3.40.0: 1.200 chars en bucle E historial)
[v] 2. Estado de HA fuera del system prompt (HECHO v3.40.0: linea [Ahora: ...] corta
       de ~150-600 chars por mensaje; el detalle se pide con tools)
[~] 3. Historial corto: NO se acorto a proposito. Con cache, un historial largo y
       ESTABLE sale gratis; uno corto que se desliza rompe el prefijo en cada turno.
       Lo recorta el resumen automatico (cada ~20 mensajes).
[v] 4. Prefijo IDENTICO turno a turno (HECHO v3.40.0: prompt estable, _ctx expandido
       de forma determinista, bucle == historial)
[ ] 5. Stopgap: enrutar al pool solo los turnos cortos (<1500 tokens nuevos,
       ~3,5 car/token) y DeepSeek el resto. Solo si tras v3.40.0 la traza
       "[llm] pool OK ... nuevos N" sigue mostrando N grandes.
[ ] 6. Fase 2: busqueda web via /v1/tools/search del pool (DuckDuckGo/Serper de
       respaldo); voz via Wyoming (Piper + Whisper) en CPU, baja prioridad.
[v] 7. Calentamiento (HECHO v3.40.0, al arrancar y tras cada caida del pool;
       max_tokens:1, timeout 180 s con reintentos) + cortacircuitos para no esperar 45 s/mensaje.
[ ] 8. Experto "pegajoso" con el pool: cada experto tiene su propio prefijo (otro
       L1 y otras tools); si el router alterna mucho, cada uno recalienta su cache.
       Medir con la traza antes de decidir.
[ ] 9. Calentar mas expertos (diagnostico, automatizacion) si se usan a menudo.
       (v3.41.0: el calentamiento pesado se sustituyo por /v1/inference/warm. Si se quiere
       calentar la CACHE del prefijo sin gasto, hace falta un modelo virtual del Core solo
       local, p. ej. jarvis-local:1.0, como alejandra-experto-local:1.0.)
