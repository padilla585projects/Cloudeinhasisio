ESTADO ACTUAL DEL PROYECTO — Jarvis AI Agent para Home Assistant
================================================================================
Ultima actualizacion: 2026-05-10
Version actual: 3.11.2

=== QUE ES ===
Agente IA autonomo especializado en Home Assistant y hub central de una red
de agentes IA. No es un chatbot — es un ingeniero domotico privado con acceso
total a: dispositivos, archivos, automatizaciones, dashboards, internet,
memoria permanente, red local, agentes IA vecinos, voz y altavoces del hogar.
Se llama JARVIS.

Filosofia: ACTUA primero, explica despues. Si no sabe algo lo busca.
Si falta una herramienta la instala. NUNCA dice "no se puede".
Es el centro de la red — los demas agentes se conectan a el.

=== STACK TECNICO ===
- Backend:      Node.js + Express (CommonJS, require())
- Frontend:     HTML/CSS/JS vanilla (archivo unico index.html, dark theme)
- Modelo:       Claude Sonnet 4.6 (principal) + Claude Haiku (background/reparacion)
- Dependencias: express, node-fetch v2.x, cors
- Docker:       Alpine + nodejs npm iproute2 iputils
- Persistencia: JSON en /data (memoria, learnings, historial, red, colaboraciones)
- Comunicacion: SSE al frontend, REST a HA, gateway externo para red de agentes

=== ENTORNO FISICO ===
- Servidor:  Proxmox VE (virtualizacion) en 192.168.10.113:8006
- VM:        Home Assistant OS (maquina virtual en Proxmox)
- Acceso:    Panel lateral de HA (ingress) + voz + Telegram
- ~787 entidades, Zigbee2MQTT, ESPHome, Alexa Media Player, OMV/NAS

=== TOOLS DISPONIBLES (40+ total) ===

Dispositivos (5):
  - get_entities         → Lista entidades por dominio (cache 30s, max 100)
  - search_entities      → Busqueda fuzzy por nombre
  - get_entity_state     → Estado + atributos de una entidad
  - call_service         → Ejecuta servicios HA
  - get_history          → Historial de estados (max 48h)

Automatizaciones (3):
  - get_automations      → Lista automatizaciones con estado
  - create_automation    → Escribe YAML en automations.yaml + reload
  - reload_config        → Recarga automations/scripts/scenes/core/all

Filesystem (4):
  - read_file            → Lee archivos en /config, /addons, /share, /media, /data
  - write_file           → Escribe en /config, /share, /data
  - append_file          → Anade al final de un archivo
  - list_directory       → Lista carpetas (recursivo opcional)

Internet (2):
  - web_search           → Busqueda DuckDuckGo (sin API key)
  - fetch_url            → Obtiene contenido de una URL

Memoria y aprendizaje (4):
  - save_memory          → Guarda preferencia/rutina/info del usuario
  - get_memory           → Consulta memoria (filtro por categoria/texto)
  - delete_memory        → Elimina nota
  - learn                → Registra aprendizaje (error/success/pattern/optimization)

Dashboards (5):
  - get_dashboards       → Lista todos los paneles Lovelace
  - get_dashboard_config → Lee config completa de un dashboard
  - update_dashboard     → Modifica dashboard (con backup automatico)
  - get_installed_frontend → Detecta cards custom/HACS/temas
  - search_hacs_resources → Busca herramientas en la comunidad HA

Instalacion y conocimiento (4):
  - scan_installation    → Escanea toda la instalacion de HA
  - check_config         → Verifica config antes de recargar
  - install_hacs_resource → Descarga e instala cards/integraciones
  - ha_knowledge         → Consulta documentacion oficial de HA

Logs (2):
  - get_system_logs      → Logs de core, supervisor, host, add-ons
  - get_error_log        → home-assistant.log (errores integraciones)

Telegram (3):
  - telegram_send        → Envia mensaje por Telegram
  - telegram_send_image  → Envia imagen/snapshot de camara
  - telegram_get_updates → Lee mensajes recibidos por el bot

Proxmox (1):
  - proxmox_api          → Gestion completa: VMs, snapshots, storage, red, estado

Sistema HA (1):
  - ha_supervisor        → Updates, reiniciar add-ons, gestionar sistema

Red local (1):
  - network              → arp_table, scan_subnet, ping, port_scan,
                           http_request, discover_agents, wol

Archivos del PC (1):
  - local_file           → Lee archivos del PC del usuario via File System Access API
                           (Chrome/Edge). Requiere que el usuario conecte carpeta.

Voz / TTS (1):
  - speak                → Habla por altavoces del hogar:
                           alexa_salon, alexa_cocina, alexa_dormitorio,
                           alexa_garaje, alexa_show, alexa_flex,
                           all_alexa (todos a la vez), ha_tts (Piper)

Red de agentes IA (1):
  - agent_gateway        → 11 acciones para gestionar la red:
                           register, sync, send, read_messages, list_agents,
                           network_status, approve_join, reject_join,
                           pending_joins, set_permission, broadcast,
                           learn_from_interaction

Chat con agentes (1):
  - agent_chat           → Habla directamente con Ollama, LM Studio,
                           LocalAI, otro Jarvis (OpenAI-compatible)

=== VOZ ===

STT (entrada de voz):
  - Web Speech API en es-ES
  - Reconocimiento en tiempo real con transcripcion provisional
  - Auto-envio al terminar de hablar
  - Indicador visual rojo mientras escucha
  - Funciona en Chrome y Edge

TTS (Jarvis habla):
  - SpeechSynthesis lee respuestas automaticamente
  - Limpia markdown antes de leer
  - Voz espanola seleccionada automaticamente (prioriza voz local)
  - Estado mute/activo persiste en localStorage
  - Se silencia al activar el microfono

Altavoces del hogar (tool speak):
  - Echo Dot salon, cocina, dormitorio
  - Echo Pop garaje
  - Echo Show 5
  - Echo Flex
  - all_alexa: todos simultaneamente
  - ha_tts: Piper (TTS nativo HA, espanol)

=== RED DE AGENTES IA ===

Identidad de Jarvis (JARVIS_IDENTITY):
  - agent_id: ha_agent
  - Role: gateway_manager / home_automation_agent
  - 14 capacidades declaradas
  - Se presenta automaticamente al registrarse y a agentes nuevos

Normas de red (NETWORK_NORMS v1.0):
  - 10 reglas: identidad, veracidad, idioma, respeto, privacidad,
    transparencia, cooperacion, confirmacion, trazabilidad, desconexion
  - Formato obligatorio de greeting (agent_hello)

Secuencia de arranque:
  t=0s   Arranca Jarvis
  t=10s  bootGatewayRegister() → se registra en el gateway si no tiene secret
         → envia presentacion a toda la red (broadcast agent_hello)
  t=15s  Primer sync → descubre agentes existentes
  t=30s  bootAgentScan() → escanea LAN buscando Ollama, LM Studio, etc.
  t=60s+ gatewaySyncLoop() → sincroniza cada 60s, detecta cambios, procesa mensajes

Colaboraciones:
  - Jarvis puede pedir favores a otros agentes sin pedir permiso
  - Todo queda registrado en /data/collaborations.json
  - Cuando un agente responde, Jarvis te lo cuenta en el chat
  - Panel de colaboraciones visible en UI con direccion, resultado y estado

=== INTELIGENCIA DEL AGENTE ===

System prompt dinamico que incluye:
  1. Personalidad JARVIS (autonomo, directo, eficiente)
  2. Contexto temporal (hora, dia, momento del dia)
  3. Estado en tiempo real (presencia, luces, clima, media, alertas) — cada 60s
  4. Mapa de la instalacion (entidades, integraciones, add-ons, archivos)
  5. Memoria del usuario (preferencias, rutinas, info guardada)
  6. Learnings destilados cada 6h (distilled_rules.json)
  7. Self-knowledge (self_knowledge.json — Jarvis puede editarlo el mismo)
  8. Conocimiento de dashboards y cards (nativas + HACS)
  9. Experticia en HA, protocolos, hardware, Proxmox, Linux
  10. Protocolo de red de agentes (identidad, normas, instrucciones)
  11. Instrucciones de autoreparacion
  12. Instrucciones de auto-evolucion

Bucle agentico:
  - Maximo 40 iteraciones por request
  - SSE streaming al frontend (feedback visual en tiempo real)
  - Errores se auto-registran como learnings
  - Preferencias se auto-guardan en memoria
  - Continuidad tras reinicio (pending_task.json)

Procesos en background:
  - updateLiveContext()    → estado en tiempo real cada 60s
  - gatewaySyncLoop()      → sync con red de agentes cada 60s
  - distillLearnings()     → destila learnings cada 6h
  - checkSelfUpdate()      → chequea actualizaciones cada 12h
  - proactiveThinkingLoop()→ pensamientos proactivos

=== AUTOREPARACION ===
  - bootSelfCheck() lee los propios logs al arrancar
  - Si detecta errores: llama a Claude Haiku con el log + codigo
  - Haiku genera el patch, Jarvis lo aplica en /app/server.js
  - Se reinicia automaticamente via supervisor API
  - Si no puede repararse: crea pensamiento proactivo para que el usuario lo sepa

=== PERSISTENCIA (/data) ===
  - memory.json            → Notas y preferencias del usuario
  - history.json           → Ultimos mensajes de conversacion
  - learnings.json         → Hasta 200 aprendizajes
  - distilled_rules.json   → Reglas destiladas de learnings
  - self_knowledge.json    → Conocimiento que Jarvis escribe para si mismo
  - house_context.json     → Resumen instalacion (se regenera cada 2h)
  - installation_map.json  → Mapa completo de la instalacion
  - gateway.json           → Secret y estado del gateway de agentes
  - agentNetwork.json      → Red: agentes, permisos, heartbeat, learnings
  - collaborations.json    → Historial de colaboraciones entre agentes
  - pending_thoughts.json  → Cola de pensamientos proactivos
  - pending_task.json      → Tarea en curso (continuidad tras reinicio)
  - backups/               → Backups automaticos de dashboards
