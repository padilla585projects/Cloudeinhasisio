ESTADO ACTUAL DEL PROYECTO — Jarvis AI Agent para Home Assistant
================================================================================
Ultima actualizacion: 2026-05-15
Version actual: 3.24.0

=== QUE ES ===
Agente IA autonomo especializado en Home Assistant. No es un chatbot — es un
ingeniero domotico privado con acceso total a la instalacion: dispositivos,
archivos, automatizaciones, dashboards, internet, memoria permanente, red local,
voz y altavoces del hogar. Se llama JARVIS.

Filosofia: ACTUA primero, explica despues. Si no sabe algo lo investiga.
INTELIGENCIA INVESTIGATIVA: ciclo INTENTAR→INVESTIGAR→APRENDER→RESOLVER
aplicado a TODO (HA, redes, hardware, codigo, cualquier dominio).

=== STACK TECNICO ===
- Backend:      Node.js + Express (CommonJS, require())
- Frontend:     HTML/CSS/JS vanilla (archivo unico index.html, dark theme)
- Modelo:       gpt-4.1-mini (principal) + gpt-4o-mini (background)
- Alt modelo:   claude-sonnet-4-6 + claude-haiku-4-5-20251001 (si se configura)
- Dependencias: express, node-fetch v2.x, cors, node-edge-tts, js-yaml
- Docker:       Alpine + nodejs npm iproute2 iputils
- Persistencia: JSON en /data
- Comunicacion: SSE al frontend, REST a HA, HTTP a agentes externos

=== ENTORNO FISICO DE ADRIAN ===
- Servidor:  Proxmox VE (192.168.10.113:8006, nodo: pve)
- VM:        Home Assistant OS (maquina virtual en Proxmox)
- Acceso:    Panel lateral de HA (ingress) + voz + Telegram
- ~787 entidades, Zigbee2MQTT, ESPHome, Alexa Media Player, OMV/NAS
- Echo Dot en salon/cocina/dormitorio, Echo Pop garaje, Echo Show 5, Echo Flex
- OMV NAS con Docker: frigate, wireguard, nextcloud, syncthing, zerotier, motioneye

=== SISTEMA NEXUS (v1.0) ===

Router dual de prompts — reemplaza buildSystemPrompt() monolitico:
  Capa 1:   regex (0 tokens, ~70% queries)
  Capa 1.5: keywords de expertos dinamicos
  Capa 2:   LLM BG_MODEL (~10 tokens output)
  Fallback: experto ha_control

12 expertos base: rapido, ha_control, diagnostico, automatizacion, archivo,
  emergencia, dev, multimedia, energia, seguridad, red, aprendizaje

20 modulos base: base, philosophy, perseverance, autonomy, ha_control,
  ha_internals, ha_config_engineering, diagnostico, automation, filesystem,
  web, network, proxmox, emergency, dev, inamovible, multimedia, energia,
  seguridad_casa, red_infra, aprendizaje, optimization

Expertos dinamicos: nexus_manage crea/edita/elimina en runtime
Health scores: 0-100 por experto, +2 exito, -8 correccion, fallback si <20

=== SEGURIDAD (3 CAPAS) ===
1. Modulo inamovible en NEXUS (en todos los expertos excepto rapido)
2. Reglas en system prompt legacy (buildSystemPrompt)
3. Hard checks en executeTool():
   - read_file bloquea /proc/ y /sys/
   - fetch_url solo GET
   - github_push requiere adrian_confirmed:true
   - append_file y write_file requieren adrian_confirmed para archivos criticos
   - patch_file: falla sin tocar si no encuentra el texto exacto

=== ENDPOINTS REST ===
  GET  /                    → UI del chat (index.html)
  POST /api/chat            → Conversacion con Jarvis (SSE)
  GET  /api/history         → Historial de conversacion
  GET  /api/greeting        → Saludo de bienvenida con estado real
  GET  /api/health          → Estado del servidor
  GET  /api/logs            → Logs internos del servidor
  GET  /api/cost            → Uso de tokens y coste estimado
  GET  /3d-map              → Visor Three.js de la casa (house_3d_map)
  GET  /api/3d-map-config   → Config JSON del mapa 3D
  GET  /api/ha-states-simple → Estados simplificados para el visor 3D
  POST /api/local_response  → Respuesta de File System Access API
